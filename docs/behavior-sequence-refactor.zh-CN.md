# 跨步骤行为评估重构

[English](behavior-sequence-refactor.md)

## 目标与边界

评估回答四个问题：执行是否遵循当时有效的计划；工具是否重复获取相同内容；任务何时获得证据、形成决定或通过验证；这些行为如何转成可验证的改进建议。

Base 记录事实，Deep 判断意义，Acceptance 验证交付，Evolve 消费已有诊断。相同问题只生成一条发现，可关联多个维度。节点完成、文件变化、输出变化本身都不证明目标完成。离线分析只读取固定 trace，不读取当前 workspace，不执行 trace 命令。

## 数据设计

1. **计划历史与执行对照**：捕获 plan 和 workflow 起止快照，兼容 content/objective 及嵌套 workflow；保存计划身份、版本、节点说明、依赖、状态和来源。按请求发生时有效的快照关联执行，明确标注关联依据；缺失或多个活动节点保持未关联。执行对照保存模型调用、工具调用、执行步骤及完成声明，Deep 再判断覆盖、偏离和改计划的合理性。Acceptance 计划独立保留。
2. **资源操作记录**：文件工具记录规范路径、实际读取字节范围、完整文件及返回内容 hash，写入记录前后 hash。分析器不通过当前文件状态反推过去。历史 trace 只使用已有内容与路径。简单单一 cat 命令可作为读取候选；复杂 shell 是可能修改资源的边界，不能假定无副作用。
3. **重复操作**：区分相同输入输出、相同资源内容、重复是否合理。相同版本和范围且未记录相关修改产生候选；修改、潜在 shell 修改、输出截断、上下文可见性均交给重点评审。相同内容不证明两次读取之间从未修改，文件 hash 也不证明独占访问。
4. **行为时间线**：确定性记录内容获取/变化、文件变化、计划变化、验证结果；这些是信号而非有效进展结论。Deep 输出有原文证据的语义进展节点：信息增量、假设排除、关键决定、有效产物变化、解除阻塞、验证。记录所在步骤、目标、证据、调用与 token 成本。连续 10 次工具调用没有可识别的新结果形成筛选候选，阈值不等于停滞判决。
5. **跨步骤重点窗口**：保留最多四轮的成本归属片段；重点评审携带相邻片段、重复操作另一端、有效计划和信号索引。相邻上下文不自动算作已评审。引用仍必须由证据读取器实际交付；有限补读、预算和断点恢复继续生效。
6. **合并与端点**：图节点按精确来源和类型合并，不以相似标签强行合并；跨片段诊断按机制与证据去重，多维关联。端点按 episode/问题记录，排序稳定，包含模型调用、工具调用、已知 token 及可测经过时间，不将重叠窗口成本相加。低效片段成本是被判定片段的已知成本，不等于可节省量。

## 展示与兼容

Base 新增行为事实区域：计划执行对照、重复操作、活动信号与低进展候选；Deep 新增有证据的进展时间线和跨步骤覆盖说明。每条记录提供来源入口。CLI 报告包含同样的核心信息。旧 v2/v3 报告缺少新字段时继续可读。

Analyzer、prompt 和 session analysis 版本递增，避免复用旧统计或语义检查点。新增文件版本元数据保持工具输入兼容。历史记录的缺失数据显式显示，不能伪造版本、因果关系或进展。

## 限制

无法从公开行动记录还原模型内部推理。新内容是否相关、否定结果是否有用、决定是否有依据，仍需有限范围的语义判断。抽样重点评审不等于全量语义覆盖。资源记录不会完整解析任意 shell，也不会证明没有外部进程写入。

## 可选计划判断的校验修复（2026-10-11）

提示词现明确要求此时返回空的计划判断列表；非正式规划仍可在 `plan_quality` 维度评估。

其他有效判断保留，不为这种局部错误额外调用模型。证据来源校验仍严格执行，未来或非活动计划不能支持遵循性结论。

有效的其他维度及进展继续保存；被剔除的条目不会计为有证据支持的结论。检查点保存具体条目位置及错误字段。

## 客观事实计算与语义解释两层实施（2026-10-11）

本次落实前两层：直接计算行为事实，再由 Deep 判断其含义。实验执行、自动应用 Evolve 建议不在此次范围内。

客观事实使用 `loom.behavior-sequence.v2`：

- 调用绑定请求发生时、对应目标下已经生效的计划。排除未生效草案；生效的空计划清除旧节点。记录无有效计划、活动节点歧义等情况。历史 trace 首次从请求暴露目标时，显式标记目标关联的推断依据。
- 直接检查当时依赖节点是否被声明完成、节点声明完成后是否仍有活动，并按目标记录节点有没有关联调用。未执行分支不自动算遗漏，声明完成不代表交付物已验证。
- 对任意工具的实际返回内容做比较，覆盖复合 shell 命令，排除耗时、命令封装等易变字段；另外记录输入是否相同。文件路径、范围、内容版本的比较继续保留写入和截断限制。
- 分别展示“结果可比较覆盖率”和“资源身份覆盖率”。文件身份不明确，不会被当成没有重复。重复调用耗时及关联模型用量按唯一调用去重；缺失测量单独计数。关联 token 不等于浪费的 token。
- 记录新返回内容、显式决定/控制动作、计划变更、文件变化、验证状态及 assurance。验证记录明确属于其他目标版本时，不作为当前目标首次通过的里程碑。
- 直接计算首次返回内容、首次显式决定/控制动作、首次检查通过、验收通过的位置，以及从目标开始累计的调用、tokens、耗时。相邻观察区间不重复归属调用，使用前缀索引避免逐条扫描全部调用及复制累计 ID 列表。
- “连续没有新的可识别结果”是可引用的候选事实；不直接判定没有有效进展。没有显式决定记录，也不代表没有推理。

Deep 每个片段最多接收 8 条优先事实，记录选中/可用数量。新增 `fact_assessments`，判断重复是否必要、偏离是否合理、内容是否有用、决定是否采用证据、验证是否适用于目标。计数、哈希、时间仍由程序计算。

判断必须引用对应动作；只引用计划文本不足以证明执行。重复内容判断需要两个端点；同一次动作的模型回答、工具参数及结果都可用于计划/控制动作解释。漏答或引用不足保留 Unknown 及具体原因。进展与诊断通过已验证引用关联事实 ID；这个关联表示来源对应关系，不表示已经证明因果。

末尾验收即使没有 solver round ID，也会进入最后片段的上下文并可支撑进展记录。Base、Deep 页面与 CLI 分别展示客观事实和语义解释，旧报告仍可读取。

真实复测发现新增事实曾使汇总输入超过 prompt 上限，现已压缩汇总条目并限制证据摘录，记录汇总条目和引文覆盖；完整局部结果仍保留在 checkpoint/bundle 中。没有提高总预算。

最终版本：`behavior-evaluation.3.8` / `behavior-rubric.3.6` / `session-trajectory.4.3`。

真实评估 `evaluation_59a5246a085741aa91d7e9a482b69687` 在原有预算内以 4 次调用、60,026 reported tokens、90.06 秒完成。16 条选中事实解释全部进入汇总，其中 15 条有合格引用，1 条因引用未覆盖对应观察而保留 Unknown；10 项维度判断中 8 项有引用支持，6 个语义进展点全部关联客观事实。分析识别出了末节点误用 `complete_node`，随后改用 `finish` 的恢复行为。引用有效仍不等于语义结论已经独立校准。

同一 trace 的 Base 无需 LLM 就计算出 4 个里程碑（第 38、68、82、86 行）、6 次已绑定计划的 solver 调用及 0 次声明依赖未满足。5 次完成工具调用中有 4 次返回结果可比较，6 次 solver 工具尝试中资源身份覆盖为 0，均明确展示。该 trace 未发现重复；复合命令重复比较由有重复内容的回归案例验证。本次没有执行任务/环境对照实验。
