# 工具调用验收与证据保留

## 修复的问题

`external` 指人工或系统无法直接观测的外部验收，不表示 external tools。
旧实现允许模型为“使用 WebSearch MCP”选择 `external`，但执行分支始终返回 blocked，
并阻止后续语义验收执行。普通任务此前仅保留最近 8 次工具输出，早期搜索也容易被后续文件操作挤掉。

## 验收分工

明确要求使用某个工具时，使用：

```json
{
  "id": "web-search-used",
  "description": "使用 WebSearch MCP 收集行星资料",
  "verifier": "tool_call",
  "scope": [],
  "check": {"tool_id": "实际已绑定的工具 ID", "min_calls": 1}
}
```

Host 校验工具 ID，并根据当前目标的真实成功调用判定。失败、MCP `isError`、solver 的口头声明、
验收自身执行的工具调用均不能充当成功证据；同一 run 的同一调用重放不会重复计数。

调用成功仅证明执行发生。空搜索结果可以满足“调用成功”，但不能证明“收集到了有效资料”。
资料相关性、来源是否支撑实现、界面行为及整体任务目标仍由独立的 `semantic` 验收判断。

由于尚无可信外部确认通道，Host 拒绝新计划中的 `external`，并给模型一次带具体原因的计划纠正机会。
真正需要人工或不可观测外部确认的要求保留在 `unresolved_requirements`，不会降级为模型自行批准。

`scope` 的规范格式是路径数组，例如 `["src/data/planets.ts"]`。单个路径字符串会无损转换成单元素数组，
不占用模型纠正机会。对象、null、空路径、超过 32 条路径或越界/敏感路径仍会拒绝，错误指出 criterion ID、
字段及具体原因。`source` 指参考来源 URL，而非源代码文件；空 URL 检查会提示改用合适的 artifact/semantic 验收。

## 证据存储与选取

- checkpoint 保存调用 ID、工具、目标指纹、成功状态、输入预览和 artifact 引用；完整输出保存在 artifact。
- 优先复用 MCP、报告、来源读取已有的 artifact。其他成功输出生成可由 operation journal 重用的证据引用。
- 语义验收优先选取明确要求的工具及外部工具证据，每个工具最多 16 条均匀采样的成功调用；无成功时展示失败记录。
- 同时选取验收 scope 涉及文件的近期证据和最近 8 次调用，总计最多 48 条。
- 输入/输出预览分别上限为 2,000/6,000 字符，再按验证模型输入预算的一半缩减，给目标、候选答案和其他检查留空间。
- 明确报告采样遗漏数、内容截断和读取失败；调用成功或证据引用不能替代缺失的内容证明。

这个过程不需要再运行 Deep evaluation。证据在 task loop 调用工具时自动记录，在最终验收时选取。

## 旧 session

恢复含 `external` 的旧计划时，保留旧计划到 history，并要求重新生成计划；旧验收不会被自动标记通过。
重规划输入包含旧计划，要求保留原有需求。旧 checkpoint 没有完整调用索引，无法凭空补回已经丢弃的历史证据；
新建任务从开始就记录完整调用索引。修复不会自动恢复或重跑已有 session。

## 回归验证

覆盖 MCP 调用成功、报错、空结果，搜索后多次读文件，checkpoint 恢复、目标变更、调用去重、
错误 `external` 计划纠正，以及执行事实通过后继续进行语义验收。MCP 与语义模型使用测试替身，
不依赖在线服务或将模型判断准确率视为确定性保证。
