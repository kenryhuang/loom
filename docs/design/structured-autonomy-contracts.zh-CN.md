# 结构化阻塞、恢复与验收

本次修改将调度状态、错误展示文案和验收证据分开。运行时禁止通过 reason/message 的内容选择恢复分支；这些字段仅用于展示和模型解释。

## 阻塞契约

`blockers.py` 定义 `code`、`phase`、`scope_id`、`recovery`、`dependency_key`、`details` 和 `schema_version`。错误来源必须提供类型或错误码；未知异常归为 `RUNTIME_FAILURE`，不猜测文案。

- 来源、角色、目标缺失或终止：每轮根据当前实体状态重新计算。已完成目标的旧来源变更不阻塞当前阶段。
- 日预算：等待预算窗口变化；累计预算：调整额度。两者都保留已有用量。
- 协议或运行错误：允许一次显式手动调度重试；同一 command_id 幂等。
- 待回答、人工暂停、结果和用量未知：手动调度不能越过，必须采用对应的回答、恢复或重新规划操作。
- 依赖、退避、执行忙：等待条件满足，不展示为需要人工介入。

执行停止使用 `stop_code`；预算拒绝还校验宿主保存的 denial 与 agent/goal/work/run 绑定。自动恢复耗尽使用布尔状态和 `RECOVERY_EXHAUSTED`，不解析错误文字。

## 验收契约

每条标准包含稳定的 `id`、`revision`、`owner_id` 和展示 `text`。标准 ID 按所有者与条目位置生成；显式修订递增版本。描述不是证据外键。目标完成条件、阶段、Goal、Work 的继承由宿主维护，最后一个集成 Goal/Work 必须包含父合同全部标准。

模型评审使用协议 v2：每项检查引用 `criterion_id`、`criterion_revision` 和 `source_refs`。阶段可以通过 `covers` 引用长期目标的标准。复用已完成 Goal 必须引用 `reuse_contract_revision`，不得暗中改写历史合同。

派发时固定合同指纹。执行结束的 `acceptance_result` 绑定该指纹、标准引用、session/run、事件游标和真实通过的验收 gate。评审提交前再次校验：

1. 标准 ID 与版本完整覆盖，无遗漏、重复和额外标准。
2. 证据属于对应阶段的 Goal，Work 已成功且合同未被替代。
3. 收据与当前合同、终结 run/session、事件游标一致。
4. 对应 run 在该游标前的最新 gate 确实通过。

失败返回结构化错误码与详情，有限次协议纠正也保留这些字段。模型声称完成或队列状态 completed 本身都不能替代执行凭证。自然语言标准的业务语义仍由现有执行验收 gate 检查；此处保证的是合同身份、证据关联和状态转换的确定性，并不宣称形式化证明任意业务结论。

## 迁移与兼容

数据库迁移 v5 是唯一兼容旧文本关联的边界。旧标准只有精确且唯一匹配时才继承父标准身份，无法关联时保留本地身份。旧执行收据只从真实 gate 重建，并标记 `legacy_gate_migration`。旧固定停止文字及预算格式仅在迁移适配器中转换一次，在线恢复不使用该逻辑。

历史 revisions 和 artifacts 不改写；迁移可重复执行。旧未知阻塞记为 `LEGACY_UNCLASSIFIED`，不按文案猜类别。尚未记录响应的旧规划记为 `UNKNOWN_RESPONSE`，不能因服务升级自动重试。已完成目标的合同摘要同步升级，避免升级触发重新规划。

回归测试覆盖文案任意变化、版本失效、跨阶段证据、旧 run、缺失/重复标准、已完成来源变更、人工暂停、一次重试、未知用量保护、预算等待、协议详情保留及迁移幂等性。
