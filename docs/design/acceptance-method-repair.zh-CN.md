# Acceptance：条件、验证方案与证据复用

验收保持任务类型无关，不增加 Git 等领域专用 verifier。

## 契约与方案

每个 criterion 的 `id`、`description`、`required` 表示不可被执行 agent
删除或改写的验收条件。`verifier`、`check`、`scope` 是验证方案，允许通过
`revise_acceptance_plan` 修改；必须提供 revision 和修改原因。

修改后保留旧计划和最初检查约束，标记对应条件需要独立复核，清除旧的待完成
验证证据并使已有通过结果失效。原检查中的必需内容、来源和工具要求仍交给
独立验收判断，不能通过换成更宽松的命令或 semantic 检查逃避要求。
未决外部要求也不能直接删除。中断且执行结果未知的验证操作先完成核对，再
修改其执行方式，避免操作 journal 身份与新命令冲突。

## Scope 与缓存

`scope` 是可选文件依赖列表；command 可以使用 `[]`。artifact 的交付路径
由框架加入依赖，不要求模型在 scope 再抄一次。所有显式路径仍检查工作区边界
及秘密文件限制，工具输入仍使用已注册 Schema 校验。

文件指纹仅用于复用旧证据：

- 小范围且可完整读取：继续校验文件内容和目录成员变化。
- 条目/字节数超限、文件读取不可用，或树中遇到不能读取的成员：不读取受限
  内容，不截短指纹来冒充完整；标记 `cache.reusable=false`，执行新的验收。
- command 未声明文件依赖：不复用先前验证结果。
- 明确越界或直接指定秘密文件：仍拒绝方案，不以缓存降级绕过路径约束。

缓存不可用不再计作任务失败，不再提示 agent 删除依赖目录来满足扫描限制。
无法建立指纹时也无法证明外部文件在检查期间完全没有变化，证据有效性限于
当前验证过程，不能据此跨恢复复用。

`finish` 内部验证与宿主最终收尾可以消费同一次即时验证结果，避免重复调用。
这份内存凭据不写入 checkpoint；新的 finish、失效、方案修改及恢复后必须重新
检查不可缓存的结果。新的验证轮使用新的操作身份；执行结果未知的操作保持
原身份用于恢复核对。

## 执行成功与条件满足

command 退出码非零仍直接失败；退出码零只是执行事实。已有的独立验收模型
调用同时复核命令输出是否支持对应条件，不额外增加一轮模型调用。修改过
验证方式的其他条件同样复核，并附上最初要求。最终每个条件只有一条合并
结果，保留 `execution_check` 和相应原始 artifact 供展开查看。

## 验证

回归覆盖空 scope、扫描超限、秘密文件不进入证据、明确越界被拒绝、同一次
收尾不重复检查、恢复后重新执行、journal 操作身份、退出码零但条件失败、
方案修改与不可删除/改写条件。历史验收计划无需直接修改数据库；下次恢复
由新代码按相同要求重新验证。

108 项相关任务、服务、执行恢复及验收事实分析测试通过；Ruff 与 diff 检查通过。
未自动恢复生产 session，也未直接修改其验收历史。
