# 分批验收与预算规划

日期：2026-11-13（Asia/Shanghai）。实现入口：`tasks/acceptance_batches.py`。

## 执行顺序

1. 宿主执行 command、artifact、source、tool_call、visual 等检查。确定性失败继续保留提前停止语义判断的规则。
2. semantic、command 结果复核和方法修订复核按证据关联分组。默认每批最多 3 项，优先共享 scope/required_tools 的标准。
3. 每批只提供本批检查及相关证据。请求预算包含提示词、环境、JSON 和响应 schema；批次目标上限为 `min(24000, 模型输入额度 × 80%)`，给协议修复留出空间。显式字符上限同样参与拆分。
4. 所有必选标准通过后，单独验收宿主 `goal`。它接收完整原始目标、约束、完整计划、当前逐项结果、独立批次凭证和原始证据样本，检查覆盖与跨项一致性。组件通过不能自动替代 goal 判断。

只有宿主确认完整结果集合全部通过、没有未解决要求、验收前后输入指纹一致，才能提交完成。

## 证据与重试

- 相同内容、输入、版本和路径的成功本地读取合并展示，保留全部等价调用 ID；执行次数仍按原始 journal 统计。命令/外部调用、不同版本及读取范围不合并。command 判断使用本次独立检查输出，显式补验仍可请求历史命令。
- 具体批次按其 scope 和工具义务从持久工具凭证获取完整相关输出，不再共享一个 48 条截断视图。普通概览仍保留原有有界抽样。
- 缺口目标优先于普通 scope；补验只处理有缺口的标准，每项一次。已经通过的同批标准不重新判断。
- 单项仍过大时分页，超长 JSON/候选报告按字符区间分片，保存原始引用和偏移，不能静默删掉尾部内容。默认每次证据视图最多 16 页，可通过 `max_evidence_pages` 调整。
- 分页模型只提取事实、矛盾、局限及证据引用，不给出通过结论。收齐所有页的观察后，再独立判断该标准；观察不足必须保留缺口。元数据本身过大、页数超限或汇总仍超限，返回明确输入预算错误。
- 协议失败、超时、后续补验失败不会抹掉已完成响应。每次合法响应先保存 artifact 和 checkpoint，然后才开始下一请求。
- checkpoint 的 pending_verification 保存各批/各页的请求摘要、结果和证据引用。恢复时只有 candidate、计划、目标、工作区依赖、工具事实及执行环境的完整指纹一致才复用；输入改变时保守废弃该轮缓存。visual 和无 scope 的 command 不跨轮复用。
- 旧检查点没有批次状态时正常重新验收；合同规则版本升级后要求新验收。最终证据清单还索引原始证据 artifact，缓存复用需验证其存在。

## 预算公式

配置新增：

| 字段 | 默认值 | 含义 |
| --- | ---: | --- |
| `batch_max_checks` | 3 | 一批最多验收目标数，goal 单独处理 |
| `batch_max_input_tokens` | 24000 | 单批输入目标上限，仍受模型上下文和字符上限约束 |
| `max_evidence_pages` | 16 | 一个证据视图最多页数 |

默认预算是可用上限，不是必须消费的额度。设：

- `U = 非 goal 标准数 + 1`：为最坏情况逐项拆批及最终 goal 预留，也覆盖确定性标准的方法复核。
- `P = 各标准实际规划过的最大分页数之和`：尚未分页时为 0；同一批重复恢复不会累加。为保守覆盖拆批，每个标准分别记数。
- `V = visual 标准数`。
- `R = max_repairs + 1`：默认 3 轮。
- `C = command 标准数`。

模型调用上限：`3 + 3 × 2 × (U + P + V) × R`。

其中规划预留 3 次；每个逻辑请求预留首次调用、格式降级和一次协议修正；每个判断预留初验和一次证据补验；visual 预留两次采集对应的独立判断。批次合并正常通过时不会用完这些预留。

时间上限：`模型调用上限 × model_timeout_seconds + R × C × command_timeout_seconds + 2 × R × V × 180`，且不低于原默认值。末项为浏览器采集的 180 秒宿主期限（包括冷启动、截图和描述），每轮预留两次，独立于视觉判断时间。单次模型超时限制仍保持原值（通常 120 秒，推理模式 180 秒），不会把总时间当作单请求超时。

例如 8 项 command：`U=9, P=0, V=0, R=3, C=8`，预留 165 次调用和 21,240 秒。模型/输出提供商限额及任务、Agent 的总 token/call/time 预算仍是外层约束。

分页需求确定后，在调用前按实际页数重算默认额度。`max_model_calls`、`max_seconds` 若由用户显式设置，则各自保持原值；额度不足时保存已经完成的进度并停止。不会因补验私自续期显式额度。Resume 的预算归档和幂等续期沿用原协议。

`public().budget.allocation` 展示计算依据和规划额度，`explicit_limits` 标出显式限制，实际使用量继续由 `model_calls` / `elapsed_seconds` 记录。

## 验证重点

回归覆盖多项整体超限但单项可验、相关证据隔离、显式缺口证据优先、补验失败保留首轮结果、批次恢复与输入变更失效、分页覆盖原文尾部、独立 goal 门及显式预算耗尽保留进度。模型使用本地假实现，测试不依赖付费在线调用。
