## 真实 judge 试跑

使用仓库已有配置 `kimi_judge`（`kimi-k2.7-code`），源为上述 smoke trace。完整尝试的预算为 prompt 200,000 字符、原始证据 240,000 字符；保存于本地忽略目录 `.loom/evaluation/v2-smoke-semantic-checked/`。

- 6 次真实模型调用：2 个批次及任务综合，各有一次证据回读。
- Analyzer usage：217,796 prompt + 49,926 completion = **267,722 token**，与原任务成本分开记录。
- 实际展开 86,393 字符；输出 8 轮评审、5 条任务诊断、2 条保留行为。
- 所有 40 个逐轮维度结果均为 unknown；5 条诊断因引用超出已读范围降为 unknown；两个要求均为 unverified。
- 最终 semantic coverage 为 **incomplete**，没有形成 task verified。

此前一次尝试还暴露了模型把 `scope` 写为泛称 `task` 的协议错误，被解析器拒绝。失败不被写成成功报告。

## 试跑后补强

这些调整已有回归测试，但没有再次付费运行完整模型校准；不得把调整后的实际模型精度视为已验证。

- 返回 `returned_ref`，明确可引用的实际字符范围；提示模型优先读取具体字段，避免反复读取整个 context。
- 指定每个批次的 `round_ids_to_review`；保留已验证的批次状态，任务综合不能覆盖它们。
- 区分 earlier records、当前请求实际可见证据与后续观察。只有早期但未注入的工具结果，不能支撑当前轮次有效性；context 判断需要当前请求证据。
- 将原始 objective 作为独立要求，避免窄化为“提交报告”。验证需要 oracle、原要求的完整覆盖，以及来源事实支持的最终版本适用性。
- 未记录版本绑定或存在后续修改时，模型自行声称 freshness confirmed 不能把要求改成 supported。

后续精度工作应以这些失败样例及其扰动为固定基线，核对具体主张、引用、漏报和成本。当前 v2 适合收集可回查事实与审阅诊断，语义输出尚不适合直接驱动自动优化。
