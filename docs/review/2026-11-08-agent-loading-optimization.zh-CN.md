# Agent 加载优化与复测

日期：2026-11-08。基线：`8b35ab1`。对应[原诊断](2026-11-08-agent-loading-performance.zh-CN.md)。

优化后，Agent 首屏不再加载 Session 列表，标签页只读取其使用的字段，Work 完整上下文在展开时才读取。后台调度不再解析全部历史 Session。性能实验支持保留现有 SQLite 和完整恢复快照，本次只增加了一个针对调度候选集的部分索引。

## 已完成的修改

1. **按路由初始化**：直达 `#/agents` 时不请求 `/v1/sessions`；进入 Sessions / Evaluation 时才加载列表。Session 列表在 SQL 中分页，只返回原接口需要的摘要字段。
2. **按标签投影**：把页面读取与完整执行快照分开。Goals 不读取工作包上下文/验收执行记录；Learning 的工作包只保留 id/state/objective；Profile、Knowledge、Overview 不读取 Session body 来检查待回答问题。待回答问题只在 Learning 加载。
3. **精简列表**：Agent 列表只返回标识、版本、状态和名称。Work 内部执行诊断使用必要字段，传给浏览器的工作包进一步缩减为队列摘要。
4. **按需展开**：Work 等待队列和历史队列在展开时创建 DOM，工作包完整详情在展开时通过已有的、带 Agent 范围校验的详情接口读取。旧服务器返回完整记录时仍可显示。
5. **减少重复请求和渲染**：标签/Agent 切换会取消过期读取；后台标签暂停轮询；列表未变化时保留 DOM；Agent GET 使用内容 ETag，304 时复用已有对象。ETag 根据完整响应生成，相关工作包或预算变化不会被 Agent revision 掩盖。
6. **缩小后台调度读取**：只读取 queued / workspace_blocked 候选及调度字段，保留 FIFO、人工优先/老化、资源互斥和清理逻辑所需的信息。缺失 resource_claims 与显式空列表的区别得到保留。
7. **索引后再验证计划**：增加 `sessions_admission` 部分索引，成员资格随 Session 更新在 SQLite 事务中维护。SQL 的 `ORDER BY rowid` 原本会使查询器放弃小索引而扫描全表，改为对已筛选的小集合排序后，确认使用该索引。
8. **独立资源接口 SQL 分页**：Agent 历史资源接口不再先读取全部记录再做 Python 切片；只读资源详情不获取写事务。

完整审计/恢复数据仍保留。当前页签的概要元数据仍覆盖该页需要的历史条目，没有宣称所有历史概要都已改为游标分页。

## 测量方法

从真实数据库的一致性只读事务中提取本次读取会用到的表，建立约 24 MB 的固定测试副本。保留全部 Session 和相关 Agent 记录；Session 列表排序所用的 events 每个 Session 只保留最新事件。优化前后读取同一副本，使用不同版本代码，各预热后采样 20 次。

调度测量只计算读取，不包括它实际不会执行的 JSON 序列化；页面/列表测量包括读取和响应 JSON 序列化。P95 是这 20 个样本的经验分位数，不是生产 SLA。宿主机仍有原服务运行，耗时会有波动；测试没有中断原服务或对其数据做写操作。

另用两个临时、只读 HTTP 服务运行原/新代码和 Chromium 页面。两者都模拟原调度线程的 20 ms 等待周期，只执行读取，不启动真实任务。catalog / knowledge 选项使用固定返回值，memory library 返回空记录，因此浏览器数字验证的是 Agent 页面链路，不代表所有学习库内容的耗时。

## 数据结构判断

**目前不需要更换数据库或把完整 Session 快照拆成多张表。** 最大收益来自不读取无关数据，以及为高度稀疏的调度候选增加小型索引。完整快照仍承担恢复与审计职责。

剩余成本主要在 Goals 的运行计数投影、Work 的执行诊断和 Learning 的待回答问题查询，仍会解析关联 Session JSON。当前样本这些页面的读取及序列化 P50 为约 45–62 ms，可以先观察实际运行负载。若历史和 Session 数量继续增长，再按测量结果考虑：

- 待回答问题的部分索引，或同事务维护的轻量运行摘要。
- 大规模历史概要的游标分页，而不只是完整详情按需加载。
- 基于事件/相关集合版本跳过服务端重算；当前 ETag 节省传输和浏览器重建，但服务端仍须组装响应来计算摘要。

## 回归验证

- 前端全量 `npm test`：300 项通过。最后补充取消标签相关读取后，Agent/导航专项 42 项通过。
- 后端全量 `pytest -q tests/service tests/autonomy`：首次 644 通过、5 失败。1 项执行时序超时单独重跑通过；1 项暴露了未关联 Session 的工作包不应新增零值统计的兼容性差异，已修复。修复后的页面、统计与执行专项共 18 项通过。
- 剩余 3 项学习流程断言失败在基线 `8b35ab1` 的源码上全部复现：`test_execution_flow.py` 的单项测试和 `test_end_to_end.py` 的两项测试，均期望 learning 为 `incomplete`，实际为 `completed`。未为本次优化修改这些既有期望，不能把整个后端测试套件报告为全绿。
- 新增检查覆盖：无关标签禁止读取 Session body、按需获取完整工作包及跨 Agent 范围检查、历史路线关联、布尔类型、Session 分页/顺序、资源互斥与索引事务回滚、304 相关记录失效和鉴权、Agent 首屏不请求 Sessions、标签切换取消过期请求。
- 修改文件 Ruff 检查及 `git diff --check` 通过。

## 复现与生效

```sh
.venv/bin/python scripts/benchmark_agent_loading.py runs/service/service.sqlite --repeats 20
# 对照版本：先把旧版本源码导出到单独目录，再对同一固定数据库副本运行
.venv/bin/python scripts/benchmark_agent_loading.py /path/to/snapshot.sqlite --source /path/to/old/src --repeats 20
```

脚本不会创建服务、启动后台任务或执行迁移，也不输出任务内容。输出中的 `admission_index` 表明数据库是否已有新索引；旧运行实例尚未创建索引时，调度数字不代表完成升级后的结果。

当前运行实例未被重启。后端修改和索引会在服务下次使用新代码启动时生效；索引创建是幂等的，已有记录无需另行迁移或删除。
