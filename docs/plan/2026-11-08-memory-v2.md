# Memory V2 实施、迁移与验收计划

日期：2026-11-08。状态：核心存储、迁移、整合、运行时和页面已实现；真实人工语义校准及可选图引擎专项仍未完成。逐项结果见[实现与迁移记录](../review/2026-11-08-memory-v2-implementation.zh-CN.md)。以下保留原验收目标，不代表每项实验均已通过。

前置文档：[总体设计](../design/memory-v2.zh-CN.md)、[参考机制及本地能力](../review/2026-11-08-memory-systems-research.zh-CN.md)。本计划不以接入某一个引擎或缩小记忆条数作为完成标准。

## 阶段 0：基线、契约和标注集

交付：可重复的数据快照采样、旧行为基线、操作契约、失败案例集、可量化门槛。

工作：

1. 固定 evaluation/record/source digest 与旧工具/页面输出样本，确认更新、删除和人工标注的全部写入入口。
2. 明确 extraction accepted、knowledge active、reviewed、fresh 的独立语义。
3. 制作至少 1,200 对人工标注样本，覆盖约 600 对等价/补充、400 对难负例、200 对冲突/时态变化；每对标注实体、条件、时间和来源关系，不只标“相似”。按证据根、项目和时间分组切分，避免同一 trace 的改写进入训练/校准和测试两侧。
4. 构建多步事件序列，而非只测静态相似句：新增 → 支持 → 冲突 → 核验 → 替代 → 删除来源 → 恢复/撤销。
5. 定义当前实际上下文 packet 的审计断言，捕获现有双路检索偏差，形成迁移前样本。

通过条件：所有状态和操作有明确前后置条件；原行为可以重放；标注含人工抽查/分歧裁决。未标注的真实历史不能用模型自行评判的“去重率”宣布质量提升。

## 阶段 1：规范化投影、版本和来源

交付：不扫描 evaluation 大 JSON 的知识/经历读取模型，完整历史与可逆迁移。

建议入口：

- `src/loom/memory/schema.py`：新增表、索引、迁移版本。
- `src/loom/memory/repository.py`：只读快照、短写事务、幂等事件和版本。
- `src/loom/memory/sources.py`：原记录/人工来源桥接、源可用性与根证据身份。
- `src/loom/memory/migration.py`：按 namespace 的回填游标、校验与旧 ID 映射。
- `src/loom/service/semantic.py`、`memory/annotations.py`：源变更写 outbox。
- `src/loom/autonomy/migrations.py`：schema 集成；保留旧 `memory_versions(id,value)` 的兼容用途。

最小阶段只需要 namespace、sources/observations、items/item_versions、validity/supports、events/outbox；实体别名和复杂关系可在后续补齐，避免初次迁移就自由生成大图。

要求：

- 不改原 evaluation 内容；同一源事件重复回填零新增。
- 原拒绝/退役墓碑先迁移，不能先让被拒绝内容短暂变 active。
- 先投影、后启用；各 namespace 有 checkpoint、校验结果和明确读取模式。
- 来源源版本发生变化时，旧来源关联必须失效或进入待核实，不能只追加新数据。
- 比较 record 内容 digest、发布状态和来源依赖生成差量；评估进度或成本字段更新不产生整合任务或知识 epoch 变化。
- 新版写入和读取能区分“未知观察时间”和“已知有效时间”。

通过条件：回填前后来源/审核映射全量可核对；重复回填及重启不重复创建；旧知识详情仍可通过原 ID 查看；新页面查询不读取 `semantic_jobs.body`。

## 阶段 2：确定性整合与冲突骨架

交付：CREATE、NOOP、ATTACH_SUPPORT、REVISE、SUPERSEDE、CONFLICT、RETIRE 的事务实现和持久任务。

建议入口：`memory/consolidation.py`、`memory/operations.py`、`memory/temporal.py`、`memory/dependencies.py`。

工作：

- 先实现精确键、根证据去重、同槽位比较、条件/时间规则。
- 保存支持 bundle、反向依赖和 conflict_set；删除来源可立即阻断不再受支持的主张。
- 模型输出保存在持久 job 中，提交失败只重放校验/事务，不自动重复调用付费模型。
- 采用 expected_revision 和作用域版本复查；事务内再次查同槽位，处理两个并发 CREATE。
- 现有 Agent budget ledger 增加可识别的 memory_consolidation 用量归属，遵循现有日预算；预算不足使任务等待，不删除上一个有效版本。

通过条件：确定性操作、故障恢复和并发幂等测试全部通过；人工纠正和 source invalidation 优先于旧后台提案；没有一次整库模型重写。

## 阶段 3：语义整合影子运行

交付：实体归一化、候选召回和语义关系提案；先不自动改写生产知识。

工作：

- 复用已有 FTS/embedding 能力，按授权范围、结构键和条件检索候选。
- 增加 equivalent / different_conditions / contradicts / uncertain 等结构化判断。
- 实现 MERGE/SPLIT 的预览、支持映射和撤销；版本依赖可追溯。
- 离线校准阈值，不沿用某论文或产品默认 cosine 阈值。
- 比较“仅精确规则”“规则 + 语义提案”“原始追加”的效果；各方案使用同输入、同模型版本和同预算。

拟定自动合并上线门槛：

- 盲测合并精确率 ≥99.5%，并报告样本量及 95% 置信区间；置信区间下界未达到 99% 时扩大样本或继续影子模式。
- 作用域越界、否定/数字颠倒、条件丢失、未来事实提前生效、同源循环支持等指定硬负例必须零误合并。
- 冲突识别召回率目标 ≥95%，单独报告漏检类型；自动解决冲突另行评估，不能拿“发现冲突”的分数替代“正确裁决”的分数。
- 在保持事实召回的前提下报告语义重复暴露减少量，不只报告删除条数。

这些是项目建议门槛，尚未运行评测。无法满足时，只关闭对应语义自动操作，确定性整理、历史分页和人工命令仍可用。

## 阶段 4：运行时与 Learning 页面切换

交付：唯一 MemoryPacket、当前知识页面、历史/冲突/证据视图和兼容工具。

建议入口：

- `memory/query.py`、`memory/packet.py`：权威过滤、预算、数据包和 digest。
- `autonomy/context.py`、`memory/runtime.py`、`tasks/assembly.py`、`llm/api.py`：统一一次检索；快照和实际提示同源。
- `service/autonomy.py`、`web/assets/views/agent-learning.mjs`：新列表、版本详情、变更和审核命令。
- `skills/store.py` / `skills/runtime.py`：知识版本与既有 Skill 依赖桥接。

要求：

- 保持合法请求边界更新；不修改已保存的工具决定。
- canonical ID 去重后再按相关性和多样性选择；冲突以一组显示。
- 当前不可用和历史查询分开；旧 read 参数只读取对应原始记录及映射。
- 标签切换和轮询不触发后台 consolidation；详情/证据按需加载。
- 缓存同时受 namespace epoch、环境指纹和下一时间边界约束。
- 生效的 Skill 仍由原有验证和执行采用流程控制。

通过条件：记录的 packet digest 等于发给模型的记忆内容 digest；列表与引用语义一致；不再因两个检索路径产生审计错配；超过 500 条历史完整可查；新版本撤回在下一合法请求边界生效。

## 阶段 5：可选 LightRAG / YakDB 投影

交付：可插拔投影契约及在本地固定版本上的能力/质量/性能结论。

先测试三个路径：本地 FTS、FTS + 向量、FTS + 向量 + LightRAG。YakDB 单独验证文档证据入口和页级来源，不把它算作已提供语义图能力。

必须通过的适配用例：

- 同一内容重复索引不重复创建有效 claim。
- 更新知识后，旧关系或摘要不能绕过权威过滤进入上下文。
- 删除共享实体的一份来源时，其他独立支持不丢失；删除唯一必要支持时立即失效。
- 同步失败、worker 退出、发布前崩溃只影响索引进度，旧 generation 可读、权威状态不回滚。
- 索引结果能映射精确 version；无法映射的生成摘要不得注入。
- 按 scope 与 revision 隔离；旧索引回放不能恢复已撤回内容。
- generation 批量发布、并发读取、回收和恢复有测试。

当前 adapter 每操作 worker 和复制 generation 的设计不直接用于高频逐条事实更新。只有完成批处理/增量适配并通过上述用例后，才决定 LightRAG 是否默认启用。无需同时上线 Graphiti 作为第二套图真值系统。

## 验收案例矩阵

| 情况 | 预期结果 |
| --- | --- |
| 同一 trace 重新评估 10 次 | 一份根证据，不增加 10 票独立支持 |
| 同一事实不同说法 | 确认等价后指向同一 memory，来源保留 |
| 同标题但不同平台/分支 | 独立条件分支，不互相替代 |
| “支持 X”和“不支持 X” | 对照时间/版本；仍重叠则形成冲突 |
| 单值变更与集合追加 | 前者可替代，后者不误删原集合成员 |
| 8080 改 9090，有明确变更日期 | 保留历史，按有效时间选版本 |
| 旧文档晚导入 | 不以导入时间覆盖当前事实 |
| 未来配置已知 | 到生效时间才切换；缓存无需写入也按边界失效 |
| 事实只在一个观察点成立 | 不伪造连续有效区间 |
| 事实到复核期但未验证 | 显示待核实，不伪装为 false 或已验证 |
| lesson 的原因仅是推断 | 保存推断状态，不因多次复述变 observed |
| 多前提教训丢失必要来源 | 依赖门禁阻断，不能因剩余一个来源继续有效 |
| 有另一个完整独立支持 bundle | 保留可用性，同时移除失效支持 |
| 人工纠正后旧后台提案提交 | revision 冲突，重新判断，不覆盖人工更改 |
| 人工拒绝后重新提取同源内容 | 墓碑阻止自动复活 |
| 两个 Agent 并发提取同一事实 | 事务内查重，最终一份 canonical 知识 |
| 错误 MERGE 后撤销 | 恢复 ID/版本关系和支持，不丢原始证据 |
| 索引仍返回 retired 内容 | 权威校验过滤，不透传旧摘要 |
| 知识前提撤回，Skill 已选择 | 下一边界撤销继续采用，保留动作历史 |
| 从 V2 回滚旧读取 | 新增拒绝仍生效，不恢复错误记忆 |
| packet 已发出后知识变化 | 原快照保持；下一请求使用新 packet |
| 数据源不可用 | 明确 degraded/error，不把异常伪装成空知识或旧事实 |

## 性能与规模测试

固定硬件、数据和模型/embedding 配置；分别测试 10k、100k 知识项，以及高重复、高冲突和高更新率场景。报告冷/热缓存、索引落后与依赖服务超时情况，不能只测命中缓存。

拟定本地目标：

- 10k 知识项列表/结构过滤 P95 ≤200 ms；100k ≤500 ms。
- 10k 知识项本地确定性召回和组装 P95 ≤300 ms，不含远程 embedding；含网络和模型的总时间单独报告。
- 读路径对 evaluation 大 JSON 的访问次数为 0；无索引结果时也不退回全量解码。
- 图召回设置独立截止时间，超时返回经权威验证的本地结果并标记降级；不阻塞页面和主执行。
- 有效知识数、实体数、支持数、版本数、索引体积、写放大、generation 清理耗时与内存峰值均记录。缓存预算按实际堆内存和序列化体积分别测量。
- 记忆变更到权威可见、索引可见、下一次上下文生效分别计时；不得用统一“同步完成”掩盖三个边界。

具体目标需要用项目数据校准，不是承诺 LightRAG/YakDB 已达到这些数值。相关远程模型调用应在正式实验时单独明确预算并记录，设计阶段未执行。

## 迁移开关和回滚

建议按 namespace 记录：`legacy`、`shadow`、`library_v2`、`runtime_v2`、`graph_enabled` 五类配置/能力标志；不是一个一次性全局开关。

每次切换前保存源游标、知识 epoch、索引 generation、比较报告及未解决项统计。回滚只改变读取/索引路由，不删除新版审计。撤回、屏蔽和来源可用性门禁跨版本生效；必要时以新拒绝视图过滤 legacy 结果。

故障测试包括模型请求超时、提交前崩溃、提交后未发布索引、索引完成但确认丢失、重复投递、并发人工修改、数据库重开、源删除中断和过时缓存。恢复后先验证权威状态，再重建投影。

## 完成定义

完成意味着一份新知识进入系统后，能以可解释方式与旧知识建立关系；重复不反复堆积，冲突与变化有明确表达，过时和撤回在读取时有效；所有实际注入都能回溯到具体版本与证据。图谱规模变大、条数变少或某个数据库已接通，都不是单独的完成标准。
