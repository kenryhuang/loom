# 自主 Agent 执行扩展：隔离目录、模型分工与流水调度

状态：实现契约。默认继续使用原只读 barrier；`parallel.mode=流水模式` 的实际配置值为 `pipeline`，写分支另需 `parallel.isolated_writes=true`。

## 支持边界

目录资源按规范化真实路径判定父子冲突；相邻目录不冲突。native_os 不是 OS 沙箱。
新增分支只开放 Host 自己实现的有界 UTF-8 文件读写，不执行 shell、外部连接器、浏览器或子进程。
因此分支没有跨目录或外部写入权限，也没有可被租约过期遗留的子进程；原生 shell 留在主线已有进程恢复协议。
符号链接、特殊文件、`.git`、超大目录不进入快照。未知副作用拒绝派发。

## 写分支协议

宿主在服务 artifact 目录下创建独立基线及工作副本，检查点保存目录、文件摘要、模型身份及输入版本。
分支写入只能到副本，结果完成后进入集成队列。主线在没有并发工具调用的边界执行集成。
集成先核验全部主线文件的基线摘要；任何变化均产生 conflict，保留副本，等待复核。
每个文件应用前后落盘 journal，重启根据 before/after 摘要对账；未知第三种状态停止，不覆盖用户新修改。
重复集成幂等。部分应用不被当作整批成功，恢复完成后才能接受该分支结果。
主任务 finish 与既有 acceptance 仍是最终验收；分支完成不是任务完成。

## 模型与预算

分支模型只允许服务配置中已存在的命名模型，保存模型配置摘要；恢复配置变化会拒绝继续旧分支。
沿用所属 Agent/Goal/WorkPackage 的 BudgetProvider，并保留分支调用身份及总 token/call 预留。
不允许通过更换模型消除旧预留，不自动重发已知副作用。

## P5.5 并发子计划

1. barrier 默认不变；pipeline 开关启用就绪节点的有界滑动窗口，先支持只读。
2. 已完成节点立即发布具名输出，依赖该结果的就绪节点可以在其他分支仍运行时开始。
3. 主线执行作为同一调度器的 `main` lane，保留 main_messages，只有显式独立、只读工具的主线节点可并发。
4. 写分支只有隔离工具，可以和只读/其他隔离副本并发；集成等待所有活跃 lane 停在稳定边界。
5. 一个父级 writer 持久化所有 lane；每个结果绑定合同摘要、输入结果 ID 和读取文件版本。版本变化标 stale，不能覆盖新结果。
6. 暂停/取消关闭所有当前协程并保存状态；单分支失败返回主线复核，其他成功结果及实际开销保留。
7. 用可控 provider 交错测试依赖提前启动、重启、输入变化、预算与集成冲突，再运行原 barrier 测试。

代表性对照仅证明协议、交接数、调用数及验收行为；fake provider 不能证明真实模型收益。
