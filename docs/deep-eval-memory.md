# Deep eval Memory

Deep eval 的 `goal_graph_v1` 增加独立的经验提取阶段。它读取固定 run 的历史 trace，
生成可检查、可保存的记忆，不执行 trace 中的指令，也不修改原任务的验收结果。

模块职责、确定性规则、结构化错误和重试/恢复约定见
[Deep Eval 分析管线与确定性校验](deep-eval-validation.zh-CN.md)。

## 使用

在 Deep eval 的 Evaluation settings 中选择 **Extract memory**，然后运行评估。
Web 新建评估默认勾选，可关闭以仅分析执行过程。结果在 **Memory** 页签展示，
支持按目标（包含子目标）筛选、展开详情和打开原始证据。Report 和导出的评估
JSON 同时包含 memory。

已有评估保持原样，显示“未提取”；要生成记忆，使用 New evaluation 创建一次
启用 memory 的评估。当前仅支持增量图分析，旧版 v2、v3、goal_loops_v1 不增加模型调用。
服务 API 可在创建 `goal_graph_v1` 评估时传入布尔值 `extract_memory: true`；
未传入时保持原有 API 行为。Resume 保留原来的开关、模型和快照。

## 四类记忆

| 内容 | 记录信息 |
|---|---|
| Stage contributions | 对所属 subgoal / goal 的关键、支持、无明显推进、阻碍或未知贡献；具体增量、关键 action 和证据 |
| Key facts | 环境、配置、已调查能力、项目事实；观察或推断、适用范围、置信度和重新核验条件 |
| Failure lessons | 触发条件、失败尝试、可确定的原因、改进做法；区分观察到的恢复与待验证建议 |
| Efficient workflows | 前置条件、执行步骤、可避免的尝试、预期收益、必须保留的检查；区分已观察路径与未验证建议 |

贡献度是有证据依据的定性判断，不根据 token、时间或 action 数量计算百分比。
同一 stage 可以跨多个提取窗口；页面保留每段分析。如果既有正向贡献又有阻碍，
显示 Mixed；存在未知片段时显示 Partial evidence。没有评估记录的 stage 显示 Unknown。
父目标关联来自已有目标分解，不把贡献分数逐层相加。

失败探索也可能排除假设、减少不确定性，不能直接认定为浪费。
工具调用成功不等于任务成功；模型的计划或自述不等于已经观测到的事实。
提取器要求引用原文，宿主校验 ID 范围、字面引用和来源，并拒绝把只有模型自述的
记录标为已观察事实。引用存在不代表其语义充分性已获得独立证明，仍需人工核对。

## 处理与保存

1. 原有元数据分析完成后，按动作窗口读取有限的输出、错误、命令及公开回答片段。
   长字段保留头尾，标注截断；不读取当前 workspace，不读取推理正文、完整消息历史或图像。
2. 模型提取贡献、事实和失败经验，逐条验证并保存。引用必须来自该请求实际提供的证据；
   无效条目不会覆盖已通过的记录。相同记录按内容 ID 去重，冲突观察按各自范围保留。
   引用所属的 action（包括验证边界事件）由宿主根据证据映射补齐，并记录补齐信息；
   模型遗漏这些来源 ID 不会导致有效引用被拒绝。不存在的 action、未提供的引用和虚构引文仍会被拒绝。
3. 对已有记忆进行分页归纳，结合原始引文提取工作流建议。历史过长时不会把所有窗口
   合成一次无限长请求；因此不保证识别所有跨窗口关联。
4. 记忆和提取窗口随 evaluation checkpoint 保存，包含 source digest、run ID、graph revision、
   goal / stage / action IDs、证据字段与范围。读取页面、重新生成投影不调用模型。

Memory 共享当前评估的模型、调用数、时间、单次请求字符和累计证据字符限制。
token 使用计入 evaluator usage，不计入原任务；增量评估仍只记账，不按 token 总量终止。
预算不足会保留已完成的图和记忆，增加对应限额后 Resume 即可，不重做已完成窗口。
校验规则升级后，Resume 优先重新校验未完成窗口已保存的响应，保留历史错误；
如果原响应已经满足新规则，该窗口不再请求模型。
Complete 仅表示安排的 memory 窗口完成审阅，不表示完整原始输出都已读取，也不表示
原任务通过验收或所有记忆已验证。

记忆当前属于该评估的产物。它不会自动加入全局知识库或注入后续 Session。
环境、配置与能力事实必须结合 host / workspace / version / 时间范围使用；条件变化时重新核验。
敏感字段和可识别凭证在提取输入与保存输出中进行过滤，不应作为经验事实留存。

## 实现入口

- `src/loom/evaluation/memory/`：协议、证据片段、可恢复提取、只读投影与报告。
- `src/loom/evaluation/goal_loops/incremental.py`：在目标图分析结束后调度 memory。
- `src/loom/service/semantic.py`：开关验证、共享预算、checkpoint 与 artifact 持久化。
- `src/loom/web/assets/views/trace-memory.mjs`：贡献、事实、失败经验与工作流视图。

自动化测试覆盖证据范围、观察与推断、敏感字段、预算恢复、持久化、旧结果和 UI。
合成 trace 测试用于验证协议和数据流，不能替代真实任务上的语义质量校准。
